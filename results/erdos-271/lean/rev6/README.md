## Contents
* 39 Lean modules (rev 5: 38; + `Liminf1675`) (`Audit/*.lean`, `*.lean`), library `Erdos271`:
  * 35 modules form the import closure of the C\* and liminf headline theorems;
  * `B16.lean` and `B16Limsup.lean` prove the 17/6 base-16 covering construction (`B16_main`, `B16_exists`, `mem_iff_blocks`, `B16_limsup`, `S16_limsup`);
  * `Composed.lean` is the exact-bundle composition of the C\* checker bundles (`ComposedC9.composed`), generated by `scripts/mk_composed.py`.
* `scripts/Headline.lean`: `#check` plus `#print axioms` for the 26 headline theorems (18 C\*/liminf, 5 for 17/6, 1 composition; rev 6: + the finite weighted integral identity, + the separate 1675 liminf term).
* `scripts/check_axioms.py`: **strict** acceptance audit (round 34; script by ChatGPT, adopted after its finding that the rev-4 count-only check accepted one valid report duplicated 24 times). It requires exactly the 26 expected headline names, each once (rev 5: 24; rev 6 adds `Erdos271.FiniteIntegrals.finite_weighted_integral_identity` and `Erdos271.Liminf1675.liminf_construction_1675`). It rejects missing, substituted, extra and duplicated reports, malformed or truncated reports, any error/panic/exception line, and any axiom outside `propext`, `Classical.choice`, `Quot.sound`. It prints JSON and exits 0 only on PASS.
* `scripts/test_check_axioms.py`: regression tests for the audit (synthetic fixtures, including the duplicated-report attack; pass the real `logs/axioms.log` as an argument to test it too).
* `scripts/replay_fresh.sh <new_dir> [--deps-from DIR]`: fresh-directory replay. It copies only the files listed in `SHA256SUMS` into a new directory (no project `.olean`, `.lake/build` or old logs). It fetches the pinned dependencies with `lake exe cache get`, or copies only `DIR/.lake/packages`, then verifies the Mathlib pin. It builds, runs the Headline file, the strict audit and its tests, the grep audit and compose_check, and re-verifies the hashes. It writes `logs/SUCCESS.json` only if every step passes.
* `scripts/grep_audit.sh`: grep for `sorry|admit|axiom|native_decide|unsafe|implemented_by|extern|opaque|ofReduceBool|decide +native`.
* `scripts/compose_check.py <dir>`: portable, fail-closed composition check of the C\* bundles. It checks the published statement hashes and the verbatim hypothesis matching, with every intermediate conclusion derived from the statements, so no sidecar files are needed.
* `scripts/mk_composed.py <dir> <out>`: regenerates `Composed.lean` byte-for-byte from `checker-bundles/`.
* `scripts/gen_bitset_certs.py`: regenerates the bitset certificate files `LiminfCert3072.lean` and `LiminfCert49152.lean`.
* `SHA256SUMS`: hashes of every file above, plus `lakefile.toml`, `lake-manifest.json`, `lean-toolchain` and `replay.sh`.
* `logs/`: the author's raw logs from a clean build.

## Build (exact commands)
```
sha256sum -c SHA256SUMS
lake exe cache get                                   # prebuilt Mathlib oleans for the pinned commit
lake build                                           # compiles all 39 project modules locally
lake env lean scripts/Headline.lean > logs/axioms.log 2>&1
python3 scripts/check_axioms.py logs/axioms.log      # expect JSON with "status": "PASS", 26 parsed / 26 unique; exit 0
python3 scripts/test_check_axioms.py logs/axioms.log # expect OK
bash scripts/grep_audit.sh                           # expect: no forbidden tokens in 39 source files
python3 scripts/compose_check.py checker-bundles     # expect: ALL OK
python3 scripts/check_c1675.py                       # expect: ALL OK (1675 bundle hashes + exact embedding in Liminf1675.lean)
```
Or run everything with one command: `./replay.sh` (this reuses whatever `.lake` the tree already has). For a clean replay, use `scripts/replay_fresh.sh /tmp/fresh-e271`. It needs elan, git, curl, python3, sha256sum and network access.

Author timings on 8 cores: `lake exe cache get` takes 2m47s; `lake build` takes 2m34s wall from clean (round 33; LiminfCert49152 alone is about 134 s; Composed about 25 s; B16 about 12 s);
`Headline.lean` takes 6 s.

## Single-term checker bundles
`checker-bundles/bN.statement.txt` and `bN.proof.txt` are self-contained (`import Mathlib` only) statement/proof pairs, in the Delegate Lean checker format:
* B1: the Lemma 2 chain (WCover + MemberTail, ending in `lemma2_full`)
* B2: Lemma 4 (`lemma4_integral`, with TriFubini)
* B4: `liminf_construction`, the 53√3/48 bound from the 768 certificate
* B5, B6, B7, B8a, B8b, B9: the rest of the C\* chain (integral identity, `lemma4_concrete`, `log_window_bound`, `h61_holds`, `erdos271_limsup` + a_k form, general S + Stanley). These compose with B1 as `b9 (b8b (b8a b1 b5 (b7 b6)))`; see `Composed.lean`.
* b16 (universal form) and b16e (existence form): the 17/6 theorem.
* c1675: Claude's liminf ≤ 1675·√3/1536 term (job 042a1cf7; statement f34ea2a5…, proof 4cab2175…), embedded verbatim as `Erdos271.Liminf1675.liminf_construction_1675`. Separate from the frozen `liminf_construction_1889`.

All of these were verified by the Delegate checker; the job ids are in the room note `grok-release-package.md`.
To check one locally, put it in `theorem t : <statement> := <proof>` after `import Mathlib`. B4 needs `set_option maxRecDepth 10000 in` in front.
